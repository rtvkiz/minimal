Minimal vs Minimus

Both projects ship small, hardened, low-CVE container images. This page is the measured comparison: 84 exact or same-major/minor version pairs, scanned with the same Grype binary against the same frozen database on 2026-10-01. Another 20 available pairs have mismatched or unknown versions and are excluded from the score.

Summed across those 84 images, Minimal carries 446 unique CVEs against Minimus's 915. That total is dominated by a handful of images on both sides, so the per-image table below matters more than the sum.

Minimus had 104 public equivalents in this run: 84 were version-matched and scored, while 20 were excluded for mismatched or unknown versions. Minimal also publishes 28 scanned images with no Minimus equivalent; those are excluded entirely rather than scored as wins.

The differences that are not CVE counts

CostMinimal is $0 for the entire catalog, with no tier above it.
LicenceEvery Minimal build recipe is MIT-licensed and in one public repo.
AuthMinimal images pull from GHCR with no account.
Rebuild cadenceMinimal rebuilds the whole catalog every 6 hours.
ProvenanceMinimal publishes cosign signatures, an SPDX SBOM and SLSA v1.0 Build L2 provenance.
Catalogue sizeMinimal is deliberately small. If breadth is what you need, it is the wrong tool.

Statements above describe Minimal, and each is checkable with the commands on the verify page. We deliberately do not characterise Minimus's pricing, licensing or roadmap here — those change, and their site is the authority on them.

Trying it

Pull any image and scan it yourself with the same tool used above:

docker pull ghcr.io/rtvkiz/minimal-python:latest
grype ghcr.io/rtvkiz/minimal-python:latest

Migrating an existing deployment? See migrating from Minimus to Minimal.

How these numbers were produced

  • Scanner: Grype 0.109.1, vulnerability DB schema v6.1.9, built 2026-10-01T06:33:48Z.
  • DB checksum: https://grype.anchore.io/databases/v6/vulnerability-db_v6.1.9_2026-10-01T00:39:44Z_1790836428.tar.zst?checksum=sha256%3Ac0d0263192d91df04b242e9a91e34cb289118fb08f1ed56eb0239eb57d7a517f
  • Platform: linux/amd64. Scan date: 2026-10-01.
  • Production latest tags were resolved to immutable digests before scanning, so the run is repeatable.
  • Every image was scanned with the same Grype binary and the same frozen database.
  • Raw Grype findings. No vendor VEX suppression was applied to anyone, including us.
  • Only publicly pullable images were scanned. No paid or private registry credentials were used.
  • Only exact or same-major/minor upstream version pairs are scored. Mismatched and unknown versions are excluded.

The full 396-row dataset, including the resolved reference and digest for every provider/image pair, is here: cve-comparison-2026-10-01.csv. The scored-pair inputs and version classifications are here: cve-comparison-pairs-2026-10-01.csv. Every figure on this page is derived from those files.

What this does not prove

Exact versions can still bundle different feature sets, and same-major/minor pairs can use different patch releases, so an individual outlier still needs inspection before it is treated as a product-level claim. A scanner reports known findings visible to one database snapshot; a low count is not proof that an image is free of vulnerabilities. An image a vendor does not publish is counted as not available — never as zero.
